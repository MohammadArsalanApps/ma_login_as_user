CONTROLLED SUPPORT ACCESS

Support users in their own Odoo context

Only members of the Impersonation Manager group can switch users, and the permission is checked on the server. Odoo continues to enforce the target user's access rights and record rules. A persistent session banner identifies the active target and provides a one-click return.

Find the right user

Search eligible users by name, login or email; switch from the systray, a user form or one selected user in the list.

Return with context

A visible session notice makes it clear whose account is active and lets the administrator return to their own session.

Set policy boundaries

Configure company and group scope, portal and administrator restrictions, required reason, maximum duration, IP allowlist and production lock.

Review the audit trail

Give auditors separate read-only access and review session timing, company, reason, source, digest, request count and ORM write count.

COMPATIBILITY & RESPONSIBLE USE

Requirements and security notes

Compatibility: Odoo 19.0 on-premise. Dependencies: base, web and mail.

The target user remains subject to normal Odoo access rights and record rules. The manager completes Odoo's regular authentication flow, including MFA when configured. The module does not read target passwords, API keys, TOTP secrets, password hashes or authentication tokens. The optional target notice posts an internal note.

Security note: Impersonation exposes the target user's data and permits actions available to that user. Use it only under your organization's data-protection policy, and validate configuration on a staging database before production use.
