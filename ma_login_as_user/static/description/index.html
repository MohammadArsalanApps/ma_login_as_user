Accountable support access

Switching is limited to the Impersonation Manager group and checked on the server. Odoo continues to enforce the target user's access rights and record rules. A clear session banner identifies the active target and provides a one-click return.

  • Search eligible users by name, login or email from the backend systray.
  • Favorite users and revisit the five most recently used accounts.
  • Switch from a user form or from one selected user in the users list.
  • Configure company and group scope, portal and administrator restrictions, required reason, maximum duration, IP allowlist and production lock.
  • Grant separate read-only access to audit records with the Impersonation Auditor group.
  • Review session timing, company, reason, source, session digest, request count and ORM write count.

Requirements and responsible use

Compatibility: Odoo 19.0 on-premise. Dependencies: base, web and mail.

The target user remains subject to normal Odoo access rights and record rules. The manager must complete Odoo's regular authentication flow, including MFA when configured. The module does not read target passwords, API keys, TOTP secrets, password hashes or authentication tokens. The optional target notice posts an internal note.

Security note: Impersonation exposes the target user's data and permits actions available to that user. Use only under your organization's data-protection policy and validate the configuration on a staging database before production use.
